Analyses

Three optional analyses are precomputed from your time series into JSON that the dashboard loads. Each reads config.json and writes one file per video (see Data & config model). Analyses are discovered, not listed — one published in a separate package joins the pipeline with no change to DIMS.

Running them

The builder runs these for you. By hand, from a study directory:

# not yet on PyPI — install from the core repository
git clone https://github.com/dims-network/dims
pip install -e dims/packages/dims-analysis

dims-analysis list                       # what is available
dims-analysis run --config config.json   # everything this study enables

Each analysis decides for itself whether it applies, by looking at its own key in config.json. Anything not enabled is skipped, and a failure is reported as a failure rather than scrolling past in a log.

RQA — Recurrence Quantification Analysis

Recurrence within a single signal: how often the signal revisits similar states over time. Each series is z-normalized; a distance matrix is thresholded to a target recurrence rate (~7%) to produce a recurrence plot, downsampled to ≤500×500 for the browser. The dashboard renders the recurrence plot with the signal as marginal traces, plus windowed metrics.

Windowed metrics (a sliding window along the diagonal): recurrence rate (RR), determinism (DET), laminarity (LAM), and longest diagonal line (L_MAX).

Cross-RQA

Recurrence between two signals — when states of signal A recur in signal B. The two series are interpolated onto a common time grid and z-normalized; the cross-recurrence matrix is thresholded the same way. The dashboard renders the cross-recurrence plot with signal 1 as the top marginal and signal 2 as the left marginal (matching the RQA layout), plus the same windowed RR/DET/LAM/L_MAX metrics.

Output shape: crqa_data[pair].visualization carries time, data_x, data_y, matrix_size and a sparse sparse_matrix; windowed_metrics carries the RR/DET/LAM/L_MAX series.

Cross-wavelet

Time–frequency coupling between two signals, via the continuous wavelet transform (Morlet) using pycwt. Produces cross-wavelet power, coherence, and phase over time and period, with AR1-based significance and a cone of influence (COI). Coherence follows Torrence & Webster (1999), smoothing the complex cross-spectrum so that unstable phase relationships cancel — which is the entire content of the measure. Results are downsampled for the browser.

Output shape: crosswavelet_pairs[pair].visualization carries time, period/freqs, power, coherence, phase, coi, and significance fields including sig95_wtc.

Reading a coherence value

Coherence does not sit at zero when two signals are unrelated. It is a ratio taken over a smoothing neighbourhood, so a handful of random phase relationships still average to something well above zero — around 0.25 in practice. A value of 0.27 therefore means nothing detected, which the raw number does not tell you.

That is what sig95_wtc is for: the 95% coherence level under a red-noise (AR1) null, computed by Monte Carlo, per period. It typically lands near 0.59. Compare against it rather than against your intuition. The summary statistic wtc_signif_fraction gives the share of usable cells that beat the null — under independence it sits at 0.05 by construction, so a value near 0.05 means no coupling was detected, however respectable the mean coherence looks.

Note sig95_xwt is a different test: it asks whether there is more joint energy here than red noise would give. That is a statement about power, not about coupling.

Results produced before September 2026 should be recomputed. Earlier versions smoothed the cross-spectrum after discarding its phase, which left the stored “coherence” tracking signal power instead of phase coupling — on real data, 70% of cells sat at exactly 1.0. Re-running the analysis is enough; nothing in your data or configuration needs to change. The correction is described in the core repository.
Pairs vs. flat list: RQA takes a flat list of data types; cross-wavelet and cross-RQA take pairs. In the builder you pick exactly which pairs to compute; by hand, list them as [["a","b"], ...] in config.json.
