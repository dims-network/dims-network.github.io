Working on DIMS

Contributing

DIMS is meant to be extended by people who did not write it — including from outside the project entirely.

Start here

All code is in dims-network/dims. Its AGENTS.md is a map: it tells you which single document to read for the task you have, rather than asking you to read everything.

Issues labelled agent-ready are self-contained — they name the files, link the contract, and state the acceptance check. Human and automated contributors alike are welcome to take them.

The rules

  • One copy of the code. If you are fixing the same bug twice, you are in the wrong repository.
  • Everything self-registers. Adding a tab or an analysis must not require editing an existing file. If it does, the contract needs fixing — say so rather than working around it.
  • Assume data is private until dims-case.json says otherwise. Never commit anything under assets/, and never move data content into an external service.
  • No build step, by design. A dashboard must still open from a plain file server years from now, on a machine nobody maintains.
  • Comment the why. The comments worth having in this codebase explain a decision or a trap, and often carry a measurement.

Extending from outside

An analysis registers through a dims.steps entry point; a tab is one self-registering file. Neither needs a change to DIMS itself. If your tool already produces a time series with a time column in seconds, the work is a unit conversion and a filename, not an integration.
